# 功能审核版使用说明

本轮交付为 Gitee 源码及虚拟机热部署版本。ISO 在功能审核通过后另行构建。

## 页面入口

登录现有管理地址后使用以下入口：

| 入口 | 功能 |
| --- | --- |
| 防火墙 → 工业安全 | 软件完整性、设备分组、网关访问矩阵、基础集中管理 |
| 防火墙 → 工业协议白名单 | Modbus TCP、S7comm、DNP3、MQTT、NC-Link 策略与日志 |
| 服务 → 应用识别 | 实时流量、应用统计、自定义匹配、内置应用/服务识别库 |
| 服务 → 入侵检测 | Suricata 原生 IDS/IPS、规则、告警 |
| 服务 → ClamAV / C-ICAP / Web 代理 | 文件下载防病毒及病毒库维护 |
| VPN → IPsec / OpenVPN | 原生 IPsec 与 SSLVPN 配置、认证、连接状态 |
| 系统 → 高可用性 | 原生 CARP、pfsync 和配置同步 |

当前使用 HTTP 管理地址 `http://192.168.255.136/`。集中管理的受管节点要求 HTTPS；为节点设置管理证书并启用 HTTPS 后再添加。不要把其他设备的账号、私钥或真实网络配置提交到仓库。

## 软件完整性

1. 在“保护文件”中每行填写一个绝对路径，保存设置。
2. 确认文件来自已审核版本，再点击“建立完整性基线”。
3. “立即校验”显示变化路径；“查看审计记录”显示历史告警。
4. 启用定时检查后，每五分钟检查一次。软件升级后先审查变更，再更新基线。

当前基线保护首页、核心防火墙脚本和工业安全后台脚本。检查 SHA-256、权限、所有者及文件缺失；不会自动接受变更。它是软件完整性检测，不具备 TPM/TPCM 信任根、远程证明或可信启动链。

## 网关侧微隔离

“设备分组”填写静态主机地址或 CIDR，组间地址不可重叠。“访问矩阵”选择源组、目标组、协议、目标端口和动作。显式拒绝优先于允许，其余纳管设备之间的流量默认拒绝；纳管范围外的流量继续由原有防火墙规则管理。

先保存基础设置，再预览和应用策略。管理来源网络用于保留访问防火墙自身 TCP/22、80、443 的通道；使用其他管理端口时，不要把管理地址纳入测试组。恢复上次策略仅切换运行策略，不改编辑区内容。已有 PF 会话正常到期后使用新策略。

审核环境保留以下示例，使用专用基准测试地址，不涉及实际业务网段：

| 设备组 | 网段 |
| --- | --- |
| 审核_PLC | 198.18.230.0/24 |
| 审核_HMI | 198.18.231.0/24 |

仅允许 HMI → PLC TCP/502，其余组间访问拒绝。可在 FreeBSD 测试机运行插件的 `tests/vnet_isolation.sh`，临时创建两个 VNET 网络，验证 TCP/502 放行和 TCP/503 阻断，退出时清理测试接口及 jail。不要把实际业务设备放入这些测试地址。

同一二层网络中不经过网关的通信不受此模块控制。它不包含端点代理或虚拟交换机微隔离。

## 工业协议与 NC-Link

当前示例限制在上述测试网段。规则默认为各自源地址、目标地址及端口范围内的默认拒绝；其他范围仍需原生 PF 规则管理。先在入侵检测中选择正确接口，再应用工业策略。

| 协议 | 本期控制粒度 |
| --- | --- |
| Modbus TCP | 请求功能码、Unit ID，使用 Suricata 原生事务解析 |
| DNP3 | 功能码；默认拒绝模式下暂不支持对象组条件的允许规则 |
| S7comm | 基本 TPKT/COTP S7 Job 的读/写操作；不涵盖 S7comm Plus、加密会话和全部 COTP 变体 |
| MQTT | CONNECT、PUBLISH、SUBSCRIBE、UNSUBSCRIBE、主题、身份及 QoS |
| NC-Link | MQTT 主题对应的操作、设备 UUID、审计；不包含机床适配器及 SCADA 数据库驱动 |

允许规则记录事务，不使用 Suricata `pass` 绕过后续请求。MQTT/NC-Link 的明文内容可检查；TLS 未终止时只能进行网络层控制。

当前虚拟机的在线 Suricata 使用 LAN **IDS/PCAP** 模式，便于在唯一管理网卡上审核。离线 IPS 回放已验证五类协议的阻断判定，包括 Modbus 连接复用、拆分及合并报文。生产流量的在线 IPS 阻断必须在合适的接口与拓扑中启用 Netmap/Divert 并验证，不把 IDS 告警当作实际丢包。

## 应用识别

采用 ntopng Community/nDPI，并在自定义匹配与原生协议识别之间加入离线域名特征库。自定义规则优先；域名按最长后缀匹配，同等特异性的冲突保留为未知，不作任意归类。

识别库包含 **1418 个应用/服务条目**。每个条目都有可触发的域名特征，并有全库自动匹配测试；类别集合、相同列表别名不计入数量。来源为 MIT 许可的 v2fly/domain-list-community，固定源提交及许可证随插件交付。该数字描述域名辅助识别库，不能等同于对所有应用变种、所有加密流量的完整 DPI 覆盖。

实时识别需要 ntopng 在捕获流量中观察到可用的服务域名。IP 地址、隐藏域名、共享服务域名或完全加密且无可用域名信息的流量可能只显示原生协议或未知。识别结果不自动生成应用封禁规则。

## 集中管理与双机同步

1. 每个受管节点安装工业安全插件，启用 HTTPS，配置证书信任。
2. 在节点创建专用 API 用户，只授予 `Industrial security: managed node` 权限并生成 API Key/Secret。
3. 在管理节点的“集中管理”中录入设备地址及凭据。TLS 验证默认开启；临时关闭仅用于明确的自签名测试。
4. 可以查询状态及项目审计日志。勾选目标节点后，先预览，再下发本机保存的项目隔离策略。

只分发隔离配置，不分发管理节点的设备凭据、文件完整性基线或其他系统配置。单个节点失败独立显示；接收端应用失败时恢复之前的隔离配置和运行规则。跨节点下发不承诺全局原子事务。

双机 HA 配置同步中新增“Industrial isolation policies”和“Industrial protocol policies”条目。两端需有相同插件及兼容 core，才能在接收同步配置后重建运行规则。普通连接状态由原生 pfsync 处理。IPsec/OpenVPN 的连接保持、重连行为及切换时间需要具体双机环境验收；6000 隧道容量未测。

## 防病毒与命令行

审核环境启用 ClamAV、C-ICAP 和仅监听 loopback 的 Squid/3128。正常下载及 EICAR 阻断已通过完整代理链验证。可通过 SSH 本地转发使用测试代理：

```sh
ssh -N -L 3128:127.0.0.1:3128 opnsense-dev
```

另一个终端使用 `curl --noproxy '' -x http://127.0.0.1:3128 <测试HTTP地址>`。任意 HTTPS 内容扫描不在当前默认配置范围内。

ClamAV 页面增加病毒库更新 HTTP 代理设置，虚拟机可填宿主机 `192.168.255.1` 与端口 `12450`。病毒库新旧与更新结果需在 ClamAV 页面核对。

```sh
ssh opnsense-dev
configctl industrialsuite status e30=
configctl industrialsuite integrity_check e30=
configctl industrialsuite isolation_preview e30=
configctl industrialsuite isolation_apply e30=
configctl industrialsuite isolation_rollback e30=
configctl indproto apply
```

## 后续热部署

本次旧 unionfs 在卸载时发生卡死，已通过 VMware 重置恢复，并按软件包清单校验恢复了原本仅存在于覆盖层的依赖文件。当前不再挂载 unionfs。不要在这台审核机执行 `make mount`。

Ubuntu 提交并推送 core/plugins 到 Gitee 后运行：

```sh
python3 Scripts/deploy-review.py
```

脚本创建备份与 ZFS 快照，按本地两个提交部署并保存日志。仅更新已提交的版本，遇到源目录的已跟踪修改或 unionfs 挂载会停止。默认不更新完整性基线；明确接受该版本时可使用 `--accept-baseline`。备份和证据保存在虚拟机 `/root/backups/`，包含敏感设备配置，不纳入 Git。

审核通过之后再进行 ISO 构建和干净安装验收。
