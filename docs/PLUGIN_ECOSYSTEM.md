# 插件生态与软件源

产品继续使用匹配当前 FreeBSD ABI、OPNsense 分支的官方签名插件仓库。当前审核机为 FreeBSD 14 / amd64、26.1 分支。界面品牌与包管理的 ABI、版本、签名和依赖元数据分别管理，不能因为改名而删除底层兼容标识，也不能直接切到不同系统分支的软件源。

## 使用

打开“系统 → 插件”，展开“软件源连接设置”，选择 HTTPS 镜像。审核环境可使用 `https://pkg.opnsense.org`，下载代理填写 `http://192.168.255.1:12450`。代理是宿主机的可达地址，不能填写虚拟机自己的 127.0.0.1。支持不带认证信息的 HTTP 代理 URL，留空直接连接；设置保存在设备配置中，不在源码硬编码。

点击“保存连接设置”后，再点击“刷新插件目录”。首次获取目录需要联网。以后打开页面、查看支持级别均只读取本地目录，不强制联网；主动刷新最长约 27 秒，失败时仍保留已有目录并显示连接失败提示。安装/重装使用相同代理；软件源签名验证保持开启，FreeBSD 通用源保持禁用。

## 状态含义

- **已安装**：插件已安装，目录中也有同名包。
- **本地定制**：项目自己维护的插件，包含应用识别、工业协议、工业安全及统一防病毒。由 Gitee 源码与项目部署流程更新，不从官方源重装同名包。
- **源中未提供**：已经取得目录，但目录中不再有此已安装插件；可能是下架、分支差异或第三方来源，需要单独核对。
- **目录待确认**：尚未取得目录，不能据此判断已安装插件是否被软件源提供。

本地构建的包可能在 `pkg query %R` 中保留 `unknown-repository`，这是实际来源信息，不伪造为官方仓库。插件页用“本地定制”表达其维护方式。官方插件重装不会覆盖定制的 `os-clamav`；安装失败也不会错误注册为已配置成功。

系统更新/升级接口继续禁用，审核部署流程将 `opnsense` 包锁定，避免插件依赖解析替换定制 core。插件本身仍需与当前分支和依赖兼容；这不等于任意版本或第三方插件都经过验证。官方插件的名称、说明和来源按其真实元数据展示。

## 诊断

软件源代理不同于 Web 下载代理、Git 的代理和防病毒病毒库代理。configd 不继承交互式 shell 的环境，因此只给 SSH 或 Git 配代理不能修复 Web 插件安装。

```sh
pkg -vv
pkg rquery -U '%n %v %R'
configctl firmware remote
configctl firmware tiers
configctl firmware catalogue_refresh
```

不要为解决目录加载失败而关闭签名校验、改包数据库来源或执行全系统升级。备份及审核证据保存在审核机 `/root/.plugin-ecosystem-backup` 指向的目录，含设备配置和包数据库，不提交 Git。
